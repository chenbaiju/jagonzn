## 维护约定

- 每个任务使用稳定编号 `TODO-001`、`TODO-002` 等，说明当前状态、现有能力边界、缺少的后端能力、前置条件及验收要求。
- 未交付的接口或能力不得写成已实现；后端交付后从后端活动队列转入Console队列，记录完成回链。新增任务沿稳定编号登记，后端子项完成不等于页面完成。
- 按功能在对应任务文档维护必要的实施、测试和中断接续记录；不写逐次操作流水、逐页布局检查或样式日志。
- Console 普通运行、调试、构建和测试产生的 `.log` 文件统一存放于工程根目录的 `logs/`，可按功能或验证批次建立子目录；不得直接存放在工程根目录、源码或文档目录。正式验收工具指定的独立证据目录按其冻结契约执行。
- 普通测试日志采用 `<功能名称>-<纳秒Unix时间戳>.log` 命名；同一轮 E2E 共用时间戳，重复运行使用新时间戳。`logs/` 和日志文件保持 Git 忽略，不纳入提交。同名历史日志迁入时须添加来源或摘要后缀，保留不同验证记录，不覆盖已有日志。
- 平台的 API、权限、错误码和架构定义以私有平台仓库的 [文档](https://github.com/chenbaiju/things-cloud/blob/master/docs/README.md) 为准，需要该仓库访问权限；这里链接权威来源，不另立合同。
- 平台全局阶段、门禁或阻塞状态见 [平台进度](https://github.com/chenbaiju/things-cloud/blob/master/docs/PROGRESS.md)，本目录不维护副本。
