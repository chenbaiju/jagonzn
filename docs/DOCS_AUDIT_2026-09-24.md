# jagonzn 知识库四维审计记录

> 日期：2026-09-24
> 范围：jagonzn/docs 全部 8 份既有 Markdown 文档，并对照 ThingsCloud 专项合同、进度、交付记录、相关实现与三个项目 POM；新增本报告及独立反馈台账后共 10 份知识库文档。
> 结论：存在过期状态、合同方向混淆和阶段依赖缺项，已校准。负责人进一步裁定：jagonzn 不得修改任何 ThingsCloud 代码或数据库表，只记录证据与建议，由 ThingsCloud 自行评审。当前仍在阶段 0，未启动业务实现。

## 1. 三句话阅读反馈

1. 核心目标是让 jagonzn 作为 ThingsCloud 租户，在独立运行的 jagonzn-service 和隔离的同构数据库中复用已交付能力、适配并验证真实设备，将不足与改进建议登记后交由 ThingsCloud 自行评审。
2. 下一主任务是阶段 0 的内核交付、版本/迁移与隔离部署基线裁定，条件满足且获启动授权后进入阶段 1 能力复用；首台设备合同在阶段 2 前冻结。
3. 当前重要受阻项是设备事件缺少通用输入处理路径，且 jagonzn 禁止修改平台代码或表结构；已登记 JPF-002 等待 ThingsCloud 评审，不能把协议解析完成当作事件闭环完成。

## 4. 设计冻结裁定记录

**状态：权限与数据库边界已于本轮获得负责人明确裁定，不再等待重复确认；平台能力是否扩展由 ThingsCloud 自行评审。**

### 矛盾点与依据

- 负责人已明确：独立建立 `jagonzn` 数据库，数据库表与所复用 ThingsCloud 版本完全一致；版本向 ThingsCloud 对齐，暂不改变 ThingsCloud 实施轨迹。已写入[service 架构 §8.1](jagonzn-service-backend-architecture.md#8.1%20保持数据库结构)与[进度 §4](PROJECT_PROGRESS.md#4.%20阶段%201：复用%20ThingsCloud%20能力)。
- 旧 service 架构 §8.1 曾允许新增业务通过独立新增表扩展；这不能与严格同构要求同时作为无条件实施授权。本轮已删除该默认许可。
- [标准接入合同 §1](../../docs/device-integration/STANDARD_PROTOCOL_ACCESS.md)排除设备事件上报；[主架构 §8.4](jagonzn-system-architecture.md#8.4%20首期必须补齐的事件与确认能力)及进度阶段 2/3 又要求逐次设备事件可靠保存。现有公共 Webhook 仅能证明既定平台事件的输出能力，不能填补这个输入与存储决策。
- 另有同类前提：正式库化、自动装配及非商业策略仍为候选建设内容。若获取可用制品必须改动共用内核，则需另行批准范围；不能把 jagonzn 阶段计划当作对 ThingsCloud 源码/迁移的隐含授权。

### 风险预估

直接在 service 加表会破坏严格同构和迁移一致性；直接把设备事件塞进属性会损失逐次事实与去重语义；未明确内核变更范围就宣称可交付，则可能迫使开发者暗改公共模块或覆盖同版本制品。结果是验证部署无法代表同一 ThingsCloud 基线，后续回沉、升级和验收依据失真。

### 提出的替代解释与最终裁定

审计曾区分两种可能解释：①严格同构，缺失能力交由平台提供；②改变约束，允许受控扩展存储。第二种解释与负责人最新裁定不符，已排除，不能再作为当前可执行选项。

负责人明确：租户 jagonzn 不能修改或改变 ThingsCloud 的任何代码或数据库表；通过接入设备登记当前不足或可改进之处，由 ThingsCloud 根据信息自行评审；证据与建议必须有独立 Markdown 文档。

据此建立[平台能力不足与改进建议](PLATFORM_CAPABILITY_FEEDBACK.md)。jagonzn 只做自身适配和已有支持路径的验证；缺少能力则登记并暂停依赖部分。ThingsCloud 决定是否修改及如何交付，jagonzn 不代改平台代码、迁移、合同或进度。以后平台正式交付后，jagonzn 跟随基线复验，而不是在本项目中直接修改公共内核。

## 5. 后续信息缺口与阶段归属

| 阶段 | 必需输入 | 不能默认的事实 |
| --- | --- | --- |
| 阶段 1 | 已批准内核坐标/制品、自动装配/角色清单、完整迁移资源、商业策略范围、数据库角色和中间件隔离配置 | 不能把骨架或普通模块 JAR 等同正式 Starter；不能把同版本号当作同制品；另库不能替代 Kafka/Redis 权限及资源隔离 |

## 6. 核对范围与验证限制

- 三个 POM 的静态基线为 Spring Boot `4.1.0`、Java `21`、应用版本 `0.0.1-SNAPSHOT`。service 的 POM 对齐发生于此前已获授权的变更，本轮审计没有再次修改 POM。
- 本轮静态核对 10 份知识库文档及 service README，共 125 个本地链接、10 个标题锚点，文件与标题均可解析；`git diff --check` 通过。三个 POM 的版本字段一致。未在 Obsidian UI 逐项点击，也未运行 Java 构建、数据库迁移或真机测试，不认领新增实现交付。
- 设备协议细节沿用已有调研，本轮未重新逐页提取原始 XLSX/DOCX，也未验证型号、固件或账号/项目的线上状态。IMEI、睡眠窗口、加密变体等仍须型号级证据。
- 复核公开产品的 [TCP 接入说明](https://www.thingscloud.xyz/docs/guide/connect-device/tcp.html)与[自定义数据流说明](https://www.thingscloud.xyz/docs/guide/device-type/custom-data.html)，仅用于校准外部产品文档事实，不将其当成本地代码能力证明。
- [ADR0143](../../docs/adr/0143-tcp-broadcast-routing-and-pending-recovery.md)中的设计时状态属于历史上下文；当前 D-190 结论取自最终资格记录和当前进度，不回写已接受 ADR 的历史正文。
