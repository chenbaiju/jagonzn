# ThingsLink 接入问题登记

设备接入 ThingsLink 时发现或怀疑的平台功能缺陷、业务问题，在本目录按独立问题新增 Markdown 文件，先在聊天汇报，交负责人评审。Jagonzn 不直接修改 ThingsLink 的代码或文件，也不修改、替换其业务 JAR、数据库表、函数或迁移。

文件按 `TL-BUG-001-问题简述.md` 递增命名，同一问题后续证据与复验更新原文件，保留首次失败。状态区分“待核实”“已复现待评审”“平台待修复”“待复验”“已关闭”及“非平台缺陷”；不能将部署配置边界、锁具固件差异或 Jagonzn 自身问题直接认定为 ThingsLink 缺陷。

每份记录至少包含：

- 问题摘要、发现时间、当前状态及影响范围。
- 固定 ThingsLink 提交/JAR 摘要、Jagonzn 候选、环境和相关合同。
- 复现前置、最小请求与操作步骤、预期结果和实际结果。
- 首次错误、脱敏日志、响应及外盘原件链接；标明实际运行、静态核对或推测。
- 已排除因素、受阻测试、可继续的独立工作及建议评审事项。
- 负责人评审结论、平台修复版本、复验步骤和实际结果；没有结果时明确待补。

真实密钥、Bearer 令牌和完整私有配置只保存在受控外盘，不写入问题文档。依赖问题的测试保持受阻，不通过绕过校验、改平台制品或伪造结果制造通过。

当前没有新增已确认缺陷记录。较早的能力边界及历史反馈保留在[平台能力反馈](../PLATFORM_CAPABILITY_FEEDBACK.md)，后继新问题在此登记并向该页增加摘要链接。
