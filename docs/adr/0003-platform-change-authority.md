# JADR-0003：jagonzn 只做自身设备适配与验证，平台变更由 ThingsCloud 独立评审

- 状态：已接受（jagonzn 项目范围）
- 归档日期：2026-09-24
- 依据：[隔离验证部署 §1、§3](../tenant-validation-and-contract-evolution.md)、[四维审计 §4](../DOCS_AUDIT_2026-09-24.md#4.%20设计冻结裁定记录)、[进度变更 JCH-004](../PROJECT_PROGRESS.md#10.%20变更记录)

## 背景

烟感、智能锁等协议可能暴露 ThingsCloud 公共接入合同或设备事件能力不足。若验证方直接修改平台实现，会混淆“设备适配可行”与“平台能力已正式交付”的证据，也会改变公共代码和数据库的责任归属。

## 决策

jagonzn 可以在自身项目中编写厂商协议适配并使用 ThingsCloud **已有受支持**的接口和配置；不得修改 ThingsCloud 任何代码或数据库表，也不得通过复制源码、覆盖 JAR、修改平台迁移、函数或权限模型绕过限制。发现不足时，在[独立反馈台账](../PLATFORM_CAPABILITY_FEEDBACK.md)记录来源、复现证据、影响和建议。ThingsCloud 自行决定是否采纳、如何改动并交付；只有正式交付且在 jagonzn 复验后，相关受阻项才能关闭。

## 备选与取舍

- jagonzn 直接把公共合同或平台代码“回沉”：越过负责人划定的权限，且无法独立判断平台正式版本的兼容性，因此不采用。
- 用 jagonzn 私有表或伪造属性暂时代替缺失事件入口：不能验证平台真实事件语义，也违反同构数据库要求，因此不采用。

## 影响与未完成项

缺少受支持入口的设备闭环保持受阻；反馈被登记或通过评审均不等于平台能力已交付。本 ADR 约束 jagonzn 的行为，不代替 ThingsCloud 自身的架构决策或实施记录。
