# JADR-0011：私有 cloud 事件的项目范围、签名轮换和受控恢复

- 状态：已接受（2026-09-28；`G3-SHC-JAG-PRIVATE-DELIVERY-1` 的同固定候选验收结果仍以专项回执为准）。
- 依据：[JADR-0010](0010-service-cloud-signed-event-forwarder.md)、[JADR-0009](0009-cloud-private-event-inbox.md)、[内网网络合同](../../../docs/reuse-entry/THINGS_CLOUD_JAGONZN_LAN_NETWORK_CONTRACT.md)。

## 四维审计

| 维度 | 结论 |
| --- | --- |
| 事实依据 | JADR-0010 的单项目消费组只提交成功 200，cloud Inbox 按来源部署、租户、项目和事件 ID 持久去重；公开 Webhook 对私网目标仍拒绝。 |
| 逻辑连贯性 | 单项目允许范围外事件直接提交 offset，不能推出整租户多项目交付。只配一把 HMAC 密钥并同时重启两端，不能推出轮换无丢失。 |
| 信息缺口 | 正式服务身份与密钥分发、客户项目开通流程、不可变候选仓库及真实设备命令结果需独立验收；本机使用受限实验凭据。 |
| 观点区分 | 已持久来源、HTTP 200 后确认、Inbox 去重与私网公开 Webhook 禁令是现行合同；有界项目允许清单、旧新两把密钥交叠和毒消息人工处置是本 ADR 的实现选择。 |

## 范围与轮换

一个 service 实例仍绑定一个部署和一个业务租户。`JAGONZN_CLOUD_PROJECT_IDS` 与 cloud 的 `JAGONZN_CLOUD_SERVICE_PROJECT_IDS` 是同一组逗号分隔的规范 UUID，至少 1 个、最多 1000 个，不接受重复；旧单项目字段仅供既有部署配置回退。其他租户的来源被本独立消费组忽略；本租户出现未映射项目时失败并保留 offset，须先把项目加入双方允许清单后重启，不可静默丢事件。cloud 按事件内原项目 ID 写独立数据库，不借用 service 业务表。

发送端只有一把当前密钥。接收端可同时装配不同 ID 的当前与上一把密钥，必须均为 32 字节；先部署接收端的新旧交叠，再切换发送端，确认积压和新事件均落盘后移除旧密钥。无旧密钥时空值必须成对出现。未知 key ID、错签名、错部署、错租户和错项目都不能写 Inbox。轮换密钥只属于本部署的私有 service/cloud 通道，不复用公开 Webhook 或发行方签名密钥。

## 失败处置

发送端对原来源超 1 MiB、摘要封套超 256 KiB、未映射项目、cloud 413、其他 4xx 和持续 5xx 返回稳定错误码；Kafka 记录确认保持关闭，正文、HMAC 和部署秘密不写失败日志。网络/5xx/可修复配置错误须先恢复接收端或密钥，然后观察同一事件 ID 落盘与消费者位点推进。源事件本身超长或损坏属于不可重试毒消息：在受控维护窗口先暂停消费组，按精确 topic/partition/offset 导出原始字节、摘要、对应 service outbox 行及处置审批，再决定修复来源或仅对该分区推进到下一 offset；不得按整个 Topic 的 `end` 跳过其他事件。逐分区跳过后需保留未投递业务事实和补偿工单，不能把该事件记作 cloud 已处理。此人工流程尚需同候选故障演练回执才可宣称完成。

上述 Inbox 的 `200` 只证明技术事实持久接收；cloud 业务投影、管理人员/场所开锁权限及设备命令结果各有自己的后续合同。
