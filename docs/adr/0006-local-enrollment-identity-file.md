# JADR-0006：现场申请使用单租户持久部署身份

- 状态：已接受（2026-09-28，G3-SHC-ENROLL-LOCAL-1）。
- 依据：[平台 ADR0216](../../../docs/adr/0216-self-hosted-entitlement-issuance-identity-and-term.md)、[申请 V1 合同](../../../docs/reuse-entry/THINGS_CLOUD_SELF_HOSTED_ENROLLMENT_REQUEST_V1.md)、[JADR-0005](0005-signed-self-hosted-entitlement.md)。

## 四维核查

| 维度 | 结论 |
| --- | --- |
| 事实依据 | 平台要求单部署、单计费租户以及部署私钥签名的同一 V1 申请；jagonzn 负责现场身份与离线传递。现有 service 仅装配运行时，尚无现场身份或申请生成。 |
| 逻辑连贯性 | 已签申请只证明私钥持有；命令参数中的租户 ID 仍是现场声明，发行方须另行审核组织归属。重复生成应复用同一部署、申请和密钥，否则发行方唯一键会冲突。 |
| 信息缺口 | 正式导入后的权威租户核对、备份恢复/换机审核、联机客户鉴权及私钥轮换尚未实现；本工具不填补这些条件。 |
| 观点区分 | 单部署单租户、Ed25519 申请和待审边界是平台合同；选择一个受限本地目录、稳定身份文件和可单独传递的申请文件是现场实现决定。 |

## 决策

由本地管理员在首个业务租户已建立后，显式提供该租户的真实 UUID，运行 jagonzn-service 可执行 JAR 的 `--prepare-enrollment` 命令。命令不启动 Web/数据库服务，不接受套餐值，也不联系发行方。首次运行生成 Ed25519 密钥、部署 UUIDv7 与申请 UUIDv7，并将身份和私钥写入专用目录；同目录的 `.tcshreq` 文件仅包含可传递的签名申请。重复运行同一租户返回逐字节相同的申请，不轮换身份；不同租户、损坏或被替换的文件均拒绝覆盖。

在 POSIX 文件系统上目录须为 `0700`、身份与申请文件为 `0600`；在支持 ACL 的文件系统上只允许文件所有者。无法验证私有权限时失败，不降级写入。目录与文件符号链接拒绝，私钥不输出到命令行、日志或申请文件。管理员只传递 `.tcshreq`，身份目录须独立备份；完整目录复制到第二个同时运行的现场并不能防克隆，合法换机仍须发行方显式转移和更高序号授权。

该申请只进入 ThingsCloud 的 `PENDING` 登记。jagonzn 运行时的权威部署/租户来源、授权导入、序号、额度和功能强制仍由 SHC-2a/2b/5a 等工作包完成；当前命令不把本机 `NONCOMMERCIAL` 转成可发行权益。
