## J0-1 jagonzn-service 独立部署健康入口

**目标与完成定义：**service 自身启动后提供 `GET /actuator/health`，返回 HTTP 200 与最小 `UP` 状态；敏感的 `env` 和 `metrics` 端点不公开。该入口只代表当前应用进程可响应，不代表数据库、ThingsCloud 内核或设备链路就绪。

**四维审计：**

- 事实依据：[进度总览阶段 0/1](../PROJECT_PROGRESS.md)要求独立部署有可复现运行证据；[实施手册 §2.1](../../../docs/DEVELOPMENT_ROADMAP.md#2.1%20单人纵向切片)要求完整可验收能力。两个 jagonzn 骨架此前各自通过 Maven `verify`，但 service 没有 HTTP 健康入口。
- 逻辑连贯性：增加服务健康入口可验证应用自身启动；不能从 `UP` 推导继承 ThingsCloud 能力、数据库迁移或设备协议已交付。
- 信息缺口：正式内核制品、迁移、凭据和基础设施仍待阶段门核对；因此本片健康语义限定为进程存活，后续如需完整就绪检查须另行定义依赖边界。
- 观点区分：jagonzn 禁止修改平台代码/表是负责人裁定；Actuator 健康端点是 Spring Boot 现成能力；仅公开最小健康状态和使用 Tomcat NIO2 是本片实现选择。

**实现：**在 jagonzn-service 内加入 Spring MVC 与 Actuator；仅暴露健康端点且隐藏组件详情。当前 Windows/Temurin 21.0.11 的默认 Tomcat NIO 在建立 JDK selector 管道时出现 `Unable to establish loopback connection`，所以该应用明确使用 Tomcat NIO2。平台 ThingsCloud 代码与配置未修改。

**验证：**2026-09-24 在 `jagonzn/jagonzn-service` 运行 `.\mvnw.cmd verify`，2 项测试全部通过并生成可执行 JAR。新测试在随机端口启动真实 Tomcat，用 HTTP 请求验证 `/actuator/health` 为 200 且正文包含 `"status":"UP"`、不含组件详情，`/actuator/env` 与 `/actuator/metrics` 均为 404。为避开同一 JDK 的 selector 管道故障，测试 HTTP 客户端使用 `HttpURLConnection`；请求仍经过真实 TCP/HTTP 和 Tomcat。

**结论：**J0-1 功能通过。阶段 0 尚未完成：内核交付、隔离部署与商业策略的门禁仍待核对；该健康入口不计作 ThingsCloud 内核复用或设备接入验收。
