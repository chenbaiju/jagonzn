# JT808 智能锁扩展

本包是`jagonzn-service`内的简工锁具JT808扩展，Java根包为`com.jagonzn.service.extension.jt808`。随现有service工程构建，后续在其进程内运行，不另建Maven工程或MQTT桥接进程。

当前已实现国密注册鉴权、本地会话接管、位置/锁状态上报及命令流水关联。软件测试覆盖本机TCP、原属性标准化/受理和原TCP下行消费者组合；后继正常service在外置独立数据库与Kafka等真实中间件上的模拟国密终端联调已通过，覆盖查询、控制超时不重发、重启去重和平台凭据撤销。固件互通及物理开锁仍未验。文档“简工专用”密钥/IV已核对并私有外置。开关`jagonzn.jt808.enabled`缺省为`false`，6808/TCP未部署或开放，此前软件测试使用本机随机端口，真实运行时测试使用16808回环端口，结束后应用均已停止；独立中间件保留运行。

完整阶段与外设运行方式统一见[开发测试计划](../../../../../../../../../docs/jt808-development-plan.md)。

## 扩展边界

- 编解码、型号/加密差异、会话、IMEI绑定和命令流水关联全部收敛在本包及子包；后续测试放在同名测试包。
- service通过正式`things-link-runtime`依赖获得ThingsLink能力，不复制平台业务源码，不更改平台仓库或直接写平台数据库表。
- 设备身份必须由受支持的认证用例签发，不能仅凭报文IMEI拼装可信身份。具体上行、会话及回复端口须按同步后的运行时合同核对，缺口登记到本项目能力反馈。
- JT808监听器与平台标准TCP/TLS入口分别管理；通过公开推送端口与预处理器组合，原消费者保留命令准入、规则与状态机。只支持直连目标，网关子设备拒绝。锁具通用应答、执行状态和物理结果分别保留；未知开锁结果不能自动重复执行。
- 配置、SM4密钥、JT808鉴权码、设备凭据和原始报文存于受限外置目录，不写入本包、示例或普通日志。
- 不增加平台数据库迁移。若后续确需新增本项目持久化能力，先说明恢复、归属与移除方式，再按原架构评估。

厂家协议原件由ThingsLink仓库的`../../../../../../../../../../things-link-device-sdk/jt808/jt808.md`与`assets/`维护。本独立仓库不复制其中密钥或整份协议；单独检出本仓库时须另行提供对应厂商材料。

## 构建与移除

使用service现有Maven Wrapper构建本工程；现行依赖已切至`com.things.link:things-link-runtime`，旧`com.things.cloud`属于历史名称；本地打包、继承审计及后继独立空库548迁移/正常应用启动已通过，历史库升级仍待验证。当前接收状态见[service说明](../../../../../../../../README.md)。

后续移除时，先关闭扩展开关、停止专用监听并恢复锁具服务器配置，再删除本包、对应测试、专属配置及Bouncy Castle直接依赖；专用部署规则与外置状态按届时明确授权处理。现有service和平台运行时依赖保留，不删除测试设备历史或回退平台数据库。本轮使用隔离本机模拟终端完成真实中间件联调，未连接实物设备或部署；参数、状态原件、容量与恢复边界详见计划。
